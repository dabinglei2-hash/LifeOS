## 产品需求与边界

愿景：帮助用户从生活记录走向可解释的计划、确认执行和持续回顾。首期服务管理员及受邀朋友，不开放公开注册。管理员管理邀请和账号状态，不因此获得读取私人健康、财务、对话或记忆的权限。

### 当前已实现

原生网页提供学习、日程、收支、习惯、目标、健康手工记录、笔记、妙想及 JSON 备份；社交仅会话演示。助手入口尚未启用。PWA 资源存在；真实设备安装和线上运行不因文件存在而视为验收。现有单人浏览器存储不具备多用户安全隔离。

### 已确认决策与目标用户流程

管理员生成限次、可撤销、到期邀请 → 用户验证身份并接受邀请 → 创建独立空间 → 登录后使用个人模块 → 主动选择 AI 可访问范围 → 查看计划草稿 → 确认后另行保存正式日程。邀请失效、已使用、登录过期、账号停用均明确提示；不允许前端自行决定身份。

典型场景：用户问今天如何安排，AI 获取本人的日程与学习概览，检索获准偏好，提出有来源的建议，创建待确认日程草稿；用户拒绝不产生正式日程。用户可查看、纠正、删除记忆，撤回授权后停止后续检索。

## 1. 产品定位

Life OS 是项目工作名，当前界面名称为“我的生活管理台”。面向主要用手机、没有编程基础的个人用户，把学习、外卖与日常收支、任务、想法和成长放在一个本地生活管理入口中。

核心体验：打开首页约 5 秒理解所选日期状态；通过快捷入口或完整今日回顾，在约 3–5 分钟内完成常用记录。这是产品目标，尚无可用性研究证明达标。

现阶段单人、本地优先、中文、USD。本轮获准提供隔离的社交前端演示；不新增真实社交后端、金融服务或登录系统。

## 3. 已锁定的业务规则

- 所有摘要基于记录实际填写的日期，不能按创建时间把历史数据归入今天。妙想的列表创建时间排序不改变记录日期。
- 财务为 USD，合计主要以整数分计算；差额＝收入−支出。旧混合账单、ID、分类快照和日报引用不能拆散或批量改写。
- 统计周为周一至周日；历史列表“近7天”为截至参考日的7天，两种口径并存，不能偷偷统一。月/年为自然月/年。
- 日均＝所选指标总额÷完整周期自然日数，包含未来日期：7、28–31、365/366天。无财务记录显示“—”，不是一笔零元交易。
- 统计只汇总主学习/收支/任务数组，日报副本不再加一次。任务完成率为四舍五入的百分比；0任务为0%。
- 旧记录无分类/标签时正常显示“未分类”/无标签，不猜测、不迁移历史正文。具体严格格式以代码校验为准。
- 资料净积累是累计收支差额；资产页净资产是手动资产减负债，两者不能混用或自动互写。
- 日程计划时间不等于实际执行；完成学习计划/外卖班次不自动创建学习或账单。任务日期仍是计划日期，独立截止日不替换它；不凭旧时间推断实际时长。
