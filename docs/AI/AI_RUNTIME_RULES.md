# AI 统一运行规则

版本：1.0 · 2026-11-02。状态：用户已确认的目标设计，尚未实现；本次只建设文档。产品Agent与Codex开发角色分离。总体入口见[索引](README.md)。

## 任务生命周期与调度责任

Main是唯一用户对话入口与派单者。调度系统维护身份注册、任务分配、队列、权限、预算、状态、执行日志、超时/失败处理及结果审核，不允许Agent自行互相调用。每任务只向授权身份暴露必要信息。普通任务可受控并行，但同一资源写入使用版本检查/事务，不让多个Agent覆盖同一文档；开发工作区仍按AGENTS串行单写。

Main先识别事实/来源/不确定项，再决定工具或专业角色；简单任务无需强行调用六角色。沿用AI_AGENT_SPEC既有初始设计阈值：每轮最多8次工具调用、60秒预算；专业分派共用总预算，不按Agent翻倍。长期任务应返回进度及明确续办任务，不能静默无限循环；这些阈值尚待压测，不是现有系统保证。

## 错误、降级与安全

| 情况 | 必须行为 |
| --- | --- |
| 认证失效、越权、注入 | 拒绝；不泄露他人资源是否存在；外部文本不能改变角色/工具规则 |
| 缺少资料或来源冲突 | 返回缺失/时间/证据；主脑解释并按需要询问，不补造个人事实 |
| 模型超时、限流、输出不合法 | 有界退避只重试可安全读取；拒绝未知字段/工具名；Main如实说明能力受限 |
| 写入/投递中断或结果未知 | uncertain；依据幂等键查状态，不盲目重放；不能用模拟成功交付 |
| 用户取消、撤权、暂停、账号停用 | 取消队列/租约和可取消执行；已产生副作用先核对结果再说明，不擅自删除以“回滚” |
| Agent异常/超时 | 记录最少错误元数据、保留已批准草稿，Main决定重新分派/停止；晚到结果不自动生效 |
| 并发修改/过期审批 | conflict，保留原文及草稿；重读并重新审核，禁止最后写入者静默胜出 |

可见对话与重要任务输入/输出进入获授权的聊天归档；工具/Agent运行日志仅记task_id、角色、资源引用、状态、耗时、授权版本和脱敏错误，禁止密钥、完整私人正文、隐藏推理。研究Agent默认禁止把用户敏感背景带进外部搜索/模型调用；确需外传先核实目的、范围、用户授权及供应商条件。

## 持久化与恢复门槛

中央数据服务为唯一入口。业务数据仍由业务模块服务维护，Agent不能直接写十个旧localStorage键或任意SQL；目标后端未实施，不在现有静态前端放密钥或假装具备多用户隔离。新业务写入需复用原验证、冲突预览、ID/日期/USD/统计规则及确认链路。

AI对话/记忆/任务/配额的目标备份必须独立设计、加密并在隔离目标恢复验证；当前JSON v11只覆盖已实现本地模块，不可声称备份未来中央AI数据。数据迁移、依赖、API费用和部署另行获准。本轮不改数据库/备份格式。

## 后续开发与验收

先读本目录索引指定必读文件；角色/协议/权限改变先更新文档再实现。开发角色按[CODEX工作规范](../CODEX_WORK_ENVIRONMENT.md)运行；不得把产品Main与Codex主控混为一个有生产权限的身份。

实施前依次完成：认证与A/B隔离 → 最小中央接口/三个工具与用户确认 → 六角色注册及受限分派 → 原文/摘要/记忆生命周期 → 主动Scheduler。每阶段用合成数据验收：跨用户读写/缓存/SSE拒绝、撤权生效、原文不被摘要覆盖、版本冲突、重复任务不重复写入、超时与uncertain恢复、额度并发与时间边界、删除后检索不命中。实体设备/线上投递和真实备份恢复需另行测试，不能从文档检查推定通过。
